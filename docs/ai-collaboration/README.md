# AI 协作记录索引（docs/ai-collaboration）

本目录是**「人如何指挥 AI 把 CampusAI 做出来」的过程证据**。

赛道背景：2026 第九届传智杯全国大学生数智创新与 AI 应用大赛 · **AI 创新应用挑战赛**（赛道 id 10039）。
该赛道官方简介的核心表述是「**Vibe Coding 以“意图主导、AI 生成代码”的全新开发范式**」
与「**锻炼 AI 协同开发能力**」。

因此本目录的份量**不低于** `backend/` 里的代码：
它证明的不是「系统能跑」，而是「这套系统是人在指挥下逐步迭代出来的」。

## 记录规范（每份都按这个骨架写）

```md
# DayNN · <一句话主题>

## 1. 本轮 Prompt（逐字原文）
<你实际发出去的那段话，不要改写、不要摘要>

## 2. Agent 的回复（原文关键段）
<原样引用，不要只写"AI 给了建议">

## 3. 发现的具体问题
<能落到文件和行号的，不要写"存在一些问题">

## 4. 第二轮 Prompt（逐字原文）
<如果有第二轮>

## 5. 改动文件与行号
## 6. 关键 diff（代码块 —— 不要用截图代替）
## 7. 真实验证结果（pytest 输出 / HTTP 响应，原样粘贴）
## 8. 剩余风险
```

### 三条硬规矩

1. **Prompt 必须逐字。** 发送前先把原文落盘到本文件，再发出去。
   这样文件时间戳 + git 提交时间就构成「prompt 先于代码存在」的时序证据。
2. **正文主体用文字与代码块。** 截图为辅。
   （反例：`Day08-Intent-Parser.md` 的「第一轮 Prompt」整段只有一张 PNG，
   评委在网页端读不到任何内容，等于没有。）
3. **不虚构。** 没有发生过的交互不要写；数字必须能在本机真实复现；
   Agent 没执行的步骤就写「未实测」。

### Day01–Day05 记录缺失

Git 历史显示工作日从 `chore: initialize project` 起算，
但 `Day01`–`Day05` 没有对应记录文件。若这几天的过程还找得到痕迹
（聊天记录、当时的截图、commit diff），建议补写；找不到就**不要编**，
在本表里如实标注为「无记录」即可。

## 新增记录的命名约定

- 开发过程记录：`DayNN-<主题>.md`（沿用现有命名）
- 对话原始日志：`CONV-NN-<主题>.md`
- 不要新建 `raw/` 之类的空目录占位（Git 不跟踪空目录，只会显得杂乱）
