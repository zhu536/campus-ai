## 1. 今日任务
实现食堂分析预测功能：历史趋势、高峰时段、未来午餐人流预测。
**严格约束**：预测方法必须保持简单（历史同期平均 + 星期修正 + 时间段修正），严禁使用复杂机器学习（如 XGBoost、神经网络）。

## 2. 架构落地与职责分离
Harness 落实了“Python计算、AI解释”的职责边界：
*   **Python负责计算**：新增 `backend/forecast.py`，严格实现简单的均值修正算法 `预测(t, h) = max(0, B + ΔW(weekday(t)) + ΔH(h))`。代码中不包含任何 SQL、不 import sqlite3，不做复杂训练。
*   **AI负责理解与解释**：Python 将计算好的只读 JSON 传递给 AI，由 AI 负责生成自然语言解释。
*   **全量测试**：新增 45 个食堂测试用例，全量回归测试 **516 passed**（教室相关 103 个测试全绿，未破坏旧功能）。

## 3. 核心亮点：修复 3 个真实 Bug
Harness 在自测中发现并修复了 3 个真实 Bug，这是今天最大的工程亮点：
1.  **字典推导覆盖**：趋势按周聚合时，同一小时三小时互相覆盖，导致周一总量 1400 错算成 200。
2.  **标记自相矛盾**：`is_peak` 先标记 `lots[0]`（早餐），之后再选出峰值，导致逻辑冲突。
3.  **格式化字符串缺失**：兜底文案 `前 {} 个高峰小时` 漏掉 `.format()`，导致用户端看到 `{}`。

## 4. 真实数据人工验证（核心证据）
在 `data/campus.db`（一食堂、午餐、75天）上跑真实链路：
*   **趋势**：日均 1751.71 人次，后半段 +9.86%（`direction: "up"`）。
*   **高峰**：12点峰值 702.35 人，阈值 0.8 → 高峰区间 `11:00-13:00`。
*   **预测**：基准 583.90 人/小时，预计 11-17（周一）总客流 1770 人次，其中 12 点 708 人。
*   **真实 AI 解释**：模型输出与 Python 算出的数字完全一致，没有自己乱算。
