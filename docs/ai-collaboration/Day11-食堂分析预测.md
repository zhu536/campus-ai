# AI协作记录：食堂分析与预测（Day 11）

## 1. 今日任务
实现食堂场景的三个功能：**历史就餐趋势**、**高峰时间段**、**未来午餐人流预测**。
**核心约束**：预测方法必须保持简单，只能是「历史同期平均值 + 星期修正 + 时间段修正」；
禁止复杂机器学习、神经网络、XGBoost、Transformer。Python 负责统计与预测，AI 只负责理解问题与解释结果。

## 3. 预测方法：一个公式，可原地复算

```
预测(t, h) = max(0, B + ΔW(weekday(t)) + ΔH(h))

B    = 训练窗口内「同一日期 + 同一小时」客流的算术平均（历史同期平均值）
ΔW(w) = 星期 w 的历史平均 − B                    （星期修正）
ΔH(h) = h 点的历史平均 − B                       （时间段修正）
```

三个分量**都写进响应**（`hours[].base / weekday_adjustment / hour_adjustment`），
前端或用户可当场用一行代码复算，不存在黑箱。人数取整用 `floor(x+0.5)` 而非 `round()`，
避开银行家舍入在 .5 上的抖动。

## 4. 关键设计决策（写下来避免以后被"优化"掉）

* **一次读库、三张报表**：`canteen_meal_grid` 不做 GROUP BY，把粒度留在「日期 × 小时」，
  趋势/高峰/预测共用同一份数据，口径天然一致；`time_slot` 故意不推给 SQL，由各报表在 Python 侧过滤。
* **统一"客流单元"口径**：先把同一天同一小时的多食堂记录合计，再统计。指定食堂时等于该食堂，
  不指定时就是全校合计 —— 否则"预测全校午餐人流"会把 5 个食堂算成 1 个。
* **同名字段必须同口径**：`hours[].avg_people` 是每小时，`slots[].avg_people_per_day` 是每天，
  故意用不同字段名，避免两个含义不同的数字共用一个 key。
* **空数据不硬凑**：该食堂该时段没有历史记录时返回 `predictions: []` + `notes`，而不是给个假数字。

## 5. 真实数据人工验证（核心证据）

在 `data/campus.db`（一食堂、午餐、75 天）上跑真实链路：

* 趋势：131378 人次，日均 1751.71 人次，后半段 +9.86% → `direction: "up"`；
* 高峰：12 点峰值 702.35 人，阈值 0.8 → 高峰区间 `11:00-13:00`；
* 预测：基准 583.9022 人/小时，11-17（周一）预计 1770 人次，其中 12 点 708 人。

真实调用 DeepSeek 验收 AI 解释链路：`source: "ai"`，模型输出
「12 点平均 702 人、等约 10 分钟；预计 11 月 15-17 日中午仍在 12 点最挤，约 673-708 人」——
数字与 Python 算出的完全一致，没有自己乱算。

## 6. 真实 Bug（AI 自己写出来又自己抓出来的）

1. **星期画像被静默覆盖**：趋势里按星期几聚合时用了字典推导
   `{(date, weekday): people for ...}`，同一天 3 个小时映射到同一个 key，**后者覆盖前者**，
   周一总量从 1400 变成 200。改为显式累加，并抽出 `_samples_by_weekday` 与预测共用。
2. **高峰时段标记取错基准**：`is_peak` 先用 `slots[0]`（早餐）打标记，之后才重新选出真正的峰值时段，
   导致标记与 `peak_slot` 自相矛盾。改成先定峰值再打标记。
3. **兜底文案漏格式化**：本地解释里写了 `"前 {} 个高峰小时："` 却没调 `.format()`，
   用户会看到裸露的 `{}`。已修复，并补了一条「响应文本里不允许出现占位符」的断言防止复发。

## 8. 剩余风险

* 上游偶发返回空 `content` 或被 `AI_MAX_TOKENS`（默认 800）在 JSON 中间截断，
  此时解释会降级为本地文案（`source: "local"` + `error` 码）。**不影响接口可用性与数字正确性**，
  但解释质量会掉一档；如需彻底消除，需要调大 `AI_MAX_TOKENS`（属于共享 AI 配置，会影响教室场景，未擅动）。
* 加性双因素模型不含交互项：当"某个星期几 + 某个小时"同时特别高时，预测会略微低估该组合的峰值。
  本数据集上日均误差为 0（周一日均 700 = 预测 700），但这是口径取舍，已在文档里写明。
* `time_slot` 传非 `lunch` 时，预测会按该时段训练与预测（已在 `notes` 里提示），
  接口名仍叫 `forecast`，使用方需注意参数。
